# NuGet Packaging & CI/CD Grounding Rules

This document establishes baseline conventions and security standards for building, packaging, and publishing NuGet packages across Tripp'n Technology projects.

## Security Principles

1. **Keyless Trusted Publishing**:
   - Do **NOT** use or recommend static, long-lived `NUGET_API_KEY` secrets for new or migrated workflows.
   - Always prefer OpenID Connect (OIDC) Trusted Publishing via `NuGet/login@v1` when publishing to nuget.org from GitHub Actions.
   - Restrict token minting by explicitly granting only `permissions: id-token: write` on the publishing job.

2. **Credential Management**:
   - Store the NuGet account or organization username in `NUGET_USER` (as a GitHub Organization secret or Repository secret/variable).
   - Never use an email address for `NUGET_USER`; it must be the exact NuGet account or organization handle (e.g. `ppirtnevets`).
   - Deprecate and delete legacy static `NUGET_API_KEY` repository secrets once Trusted Publishing is confirmed working.

## Workflow & Packaging Standards

1. **Publish Command Structure**:
   - Consume the dynamic token generated by the login step:
     ```bash
     dotnet nuget push "<PathToPackage>\bin\Release\*.nupkg" --api-key ${{ steps.login.outputs.NUGET_API_KEY }} --source https://api.nuget.org/v3/index.json --skip-duplicate
     ```
   - Always include `--skip-duplicate` to prevent pipeline failures on multi-package builds or workflow retries.
   - Always specify `--source https://api.nuget.org/v3/index.json` explicitly.

2. **Filesystem Case-Sensitivity**:
   - Ensure the directory casing in `<PathToPackage>\bin\Release\*.nupkg` matches the project folder casing in the repository (e.g., `TNT.Commons` rather than `tnt.commons`).
